# yoxi 微行程｜AI 模型與 API 成本試算

資料核對：2026-09-25～26。用途：提案簡報及評審追問。金額皆為美元牌價試算，臺幣統一採 **US$1 = NT$32 的預算匯率**，不是即時匯率。

## 先區分可證實的事實與預算假設

- **程式可證實：**模型 ID、各端點是否呼叫 AI、輸出 token 設定、地點查詢數、路線候選數、快取範圍。
- **線上可證實：**讀取公開 `/health`，當時回傳 `provider: geoapify`、`openRouterConfigured: true`、Google 兩項設定均為 false。這證明服務配置，不等於每次請求都成功用了 AI。
- **官方牌價可證實：**GPT-5 mini 輸入／輸出價格、OpenRouter Standard 平台費、Geoapify 點數與方案、Cloudflare Workers 方案。
- **目前尚未取得：**帳戶帳單、OpenRouter Activity 匯出、實際輸入／輸出 token 分布、Geoapify 每日實耗、快取命中、重试率及 CPU 使用量。現有 Worker 處理模型結果後沒有持久保存 usage/cost，不能把下列範圍寫成「實測平均」。

本報告未修改或部署產品程式，也未新增付費生成測試。下列為「目前架構＋官方單價＋明示使用量假設」的工程試算。

## 1. 目前使用的模型與服務

|層次|實際名稱／設定|用途|
|---|---|---|
|語言模型|OpenAI **GPT-5 mini**|需求結構化、候選選點、理解文字修改|
|呼叫平台|**OpenRouter**；模型 ID `openai/gpt-5-mini`|模型 API 路由；不是模型本身|
|推理設定|`reasoning.effort: minimal`；`exclude: true`|低推理用量設定，推理文字不回傳；不代表推理 token 免費|
|輸出契約|嚴格 JSON Schema|限定欄位與既有候選 ID，再由程式驗證|
|POI 與步行路線|**Geoapify Places API / Routing API**|真實地點、距離與步行秒數|
|前端地圖|**MapLibre GL JS + Geoapify 圖磚**|地圖顯示；MapLibre 是程式庫，圖磚另有 API 用量|
|前端／後端|**Cloudflare Pages / Workers**|静態原型與 API 後端|

模型名稱來自 `yoxi-city-guide-demo/worker/src/index.js:6`。各 AI 呼叫均引用同一常數。這是現有程式設定；沒有供應商 Activity 紀錄便不能保證所有歷史請求都由哪個上游端點處理。

簡報可說：**「以 GPT-5 mini 理解需求、挑選真實候選，Geoapify 提供地點與步行路線，再由程式驗算時間與限制。」**

不是自行訓練的模型，也不是讓模型自己編造地點或直接保證路線可行。現在沒有 embedding、向量資料庫、語音或影像 API 的產品費用項目。

## 2. AI 單價與計算公式

GPT-5 mini 標準文字價格：

|計價項目|每 100 萬 tokens|每 1,000 tokens|
|---|---:|---:|
|輸入|US$0.25|US$0.00025|
|輸出，包含計費推理 tokens|US$2.00|US$0.00200|

來源：[OpenAI 模型定價](https://developers.openai.com/api/docs/models/gpt-5-mini)、[OpenRouter 模型頁](https://openrouter.ai/openai/gpt-5-mini)。本次不預先扣除 prompt caching 或 Batch 折扣。

現有程式使用 `provider.sort: latency`，並未鎖定最低價的單一上游。OpenRouter 模型頁亦列有不同端點價格，因此本表是 US$0.25／2.00 標準牌價情境，不是所有路由的保證價；實際應以各筆 `usage.cost`／帳單為準。

```text
模型費（美元）= 輸入 tokens × 0.25 / 1,000,000
             + 計費輸出 tokens × 2.00 / 1,000,000

AI 臺幣預算 = 模型費 × 1.055 × 32
```

1.055 是以 OpenRouter Standard 5.5% 平台費攤提的假設；不是說模型每次 API 多出一個固定費用。帳戶若為 Business、BYOK 或其他付款方式，需用實際條件重算；此处未核對帳戶方案。稅、付款匯差及實際儲值結帳差異另計。[OpenRouter 平台定價](https://openrouter.ai/pricing/)

`exclude: true` 只隱藏推理文字，計費仍需看 usage，不能只數畫面上的 JSON。輸出設定是預算限制參考，不是每次實際使用量，也不作跨供應商絕對帳單上限保證。[推理 token 計價說明](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)

## 3. 每種 AI 操作的用量範圍

**以下輸入量和低端輸出量是工程預算假設，尚未用實際 API usage 量測；高端輸出以程式設定作壓力預算。** 輸入須包含系統提示、使用者條件、JSON Schema、候選名稱與 ID，不是只計使用者輸入的幾個中文字。

|操作|端點|輸入 tokens 假設|計費輸出 tokens 假設|程式 `max_tokens`|單次模型費 US$|含 5.5% 攤提的 NT$|
|---|---|---:|---:|---:|---:|---:|
|生成候選方案|`/api/plan`|1,500–4,000|100–512|512|0.000575–0.002024|**0.0194–0.0683**|
|解析一句需求|`/api/intent`|1,000–2,000|200–1,100|1,100|0.000650–0.002700|**0.0219–0.0912**|
|理解一次非快捷文字修改|`/api/refine-intent`|1,200–2,500|200–1,600|1,600|0.000700–0.003825|**0.0236–0.1291**|

引用程式：`worker/src/index.js:51`、`:80`、`:385`。輸入量上限不是程式硬上限，候選文字變長仍可能超出假設。輸出欄包含推理額度，不能再把推理 token 重複加一次。

## 4. 使用者一次操作會呼叫幾次 AI？

|情境|模型呼叫數|AI 臺幣試算|
|---|---:|---:|
|用輪盤選條件，生成一次一般方案|1|**約 0.02–0.07 元**|
|輸入一句需求，再生成一次一般方案|2|**約 0.04–0.16 元**|
|輸入需求、生成，再作一次需 AI 理解的文字修改並重新生成|4|**約 0.08–0.36 元**|
|輪盤找洗手間，由規則選點|0|AI 為 0；地圖費仍存在|
|洗手間需求先用文字輸入|通常 1|需求解析約 0.02–0.09 元；選點走規則|
|「走近一點」快捷修改|該次修改與比較本身 0|程式重算路線，仍消耗地圖 API|

第三列為一般非洗手間、非更近比較的成功路徑，未含額外重試。模型失敗後改走規則，也不代表前面的模型呼叫必然免費。簡報不要把「一次點擊」當成「一次付費 API」。

## 5. 地圖 API：容易漏算的主成本

目前以 Geoapify 試算，不把未啟用的 Google Maps API 併進現況成本。

|服務|官方計費單位|現有程式行為|
|---|---|---|
|Places API|每次最多 20 筆結果為 1 credit|每類查 8 筆，依目的搜尋 **1–4 類**|
|Routing API|每段路線為 1 credit；本案短步行路線按單段計|先算起點到 **最多 16 個候選**，再驗算站間與返回|
|Map Tiles|每張圖磚 0.25 credit|隨平移、縮放、裝置、載入及快取不同而變動|

來源：[Geoapify 計費明細](https://www.geoapify.com/pricing-details/)。一般單次成功方案，在假設 8–16 個候選、無額外失敗重試下：

```text
地點查詢：1–4 credits
路線查詢：8–19 credits（候選路線＋最多 2 段站間＋1 段返回）
畫面圖磚：假設 20–80 張，即 5–20 credits
合計：約 14–43 credits / 一次開啟並規劃
```

這不是所有情況的最大值：驗證失敗換候選、「更近」逐一比較、重新規劃或更多地圖操作都可能增加用量。程式的路線快取只在同一 `/api/plan` 請求內共用，下一次規劃會重新建立，不能假設跨次免費。

影片中的「找室內待著」會搜尋商場、博物館、咖啡館與超商 4 類；若找到 16 候選且第一個單站返回方案就成功，後端約 **4 + 16 + 1 = 21 credits**，再加實際地圖圖磚。洗手間為兩類，相同條件約 **2 + 16 + 1 = 19 credits**；第二段換方案又會新增查詢，不能把兩段展示算成一回。

## 6. Geoapify 與 Workers 方案

Geoapify 月繳牌價：[官方方案](https://www.geoapify.com/pricing/)。

|方案|每日 credits|每月 US$|NT$（匯率 32）|
|---|---:|---:|---:|
|Free|3,000|0|0|
|API 10|10,000|59|1,888|
|API 25|25,000|109|3,488|
|API 50|50,000|179|5,728|
|API 100|100,000|299|9,568|
|API 250|250,000|609|19,488|

**credit 是方案用量，不是每個 credit 有固定現金單價。** 不能把免費額度內的現金支出為零解讀為無限擴張免費，也不能拿滿額攤提單價套用在用量很少的訂閱上。

以每回 35 credits 的預算假設，免費額度約容納 **85 回／日**（3,000 ÷ 35 向下取整）。這是純點數容量，不是壓測所得服務容量；還需看尖峰與每秒請求限制。現行候選路線採並行查詢，實際上線要處理排程／併發，不能只憑月總額判斷方案足夠。

Cloudflare Workers：免費方案每日 100,000 請求、每次 10ms CPU 限制；付費標準方案基本 US$5／月，含 1,000 萬請求及 3,000 萬 CPU-ms，超額請求 US$0.30／百萬、CPU US$0.02／百萬 CPU-ms。外部 API 等待時間與 CPU 時間不同。[Workers 官方價格](https://developers.cloudflare.com/workers/platform/pricing/)

目前未讀到帳戶訂閱與 CPU 實耗，因此下表的免費或付費 Workers 都是預算配置假設。

## 7. 可重算的月成本示例

為了避免混用情境，以下全部採**一個明確基準案例**，不是實測平均：

- 每回：文字需求解析一次＋一般方案生成一次，不修改、不重試。
- 解析：輸入 1,500、計費輸出 500 tokens。
- 生成：輸入 2,500、計費輸出 300 tokens。
- 合計每回輸入 **4,000**、輸出 **800 tokens**。
- 模型費：4,000 × 0.25 / 1M + 800 × 2 / 1M = **US$0.0026／回**。
- 加 5.5% 平台費攤提：**US$0.002743 ≈ NT$0.0878／回**。
- 地圖：3 次地點查詢＋16 次候選路線＋1 次返回＋60 張圖磚 = **35 credits／回**。
- 每月 30 天，流量平均分布。1,000 回採免費地圖與免費 Workers；其餘採表列地圖套餐、Workers US$5，假設 CPU／請求仍在含量內。

|---|---|---:|---:|---:|---:|---:|---:|---:|

|10,000|4,000 萬／800 萬|350,000|11,667|27.43|109|5|**約 4,526**|0.453|

選 API 25 / API 250 是因基準案例的每日點數分別超過 API 10 / API 100。點數是每日額度，不能用月平均掩蓋單日爆量。10 萬回的單位成本低於 1 萬回來自套餐攤提，不是模型越用越便宜。

## 8. 簡報直接可用的文案

**AI 與驗證分工**

> 使用 GPT-5 mini（OpenRouter），負責需求解析與真實候選選點；Geoapify 提供地點與步行路線，程式負責時間、返回及限制驗算。

**成本**

> 依目前 API 架構與官方牌價試算：一次一般方案的 AI 費約 NT$0.02–0.07；若包含自然語言需求解析，約 NT$0.04–0.16。以每月 1 萬回「需求解析＋規劃」、每回 35 地圖 credits 的基準情境估算，AI、地圖及 Workers 合計約 NT$4,526／月，平均約 NT$0.45／回。

頁腳建議：**工程試算，非正式營運實績；USD/TWD=32、OpenRouter Standard 5.5% 攤提，未稅；不含重試、人力及正式串接。牌價核對 2026-09-25～26。**

評審問「成本為什麼不是只看模型？」可答：**目前一次規劃會驗算多個真實候選的步行路線，所以地圖查詢與重規劃次數是另一個重要成本來源。**

## 9. 若要把「試算」升級為「實測」

需要 OpenRouter Activity 的同一期間匯出、Geoapify 每日／各 API 統計、Cloudflare 計费與使用量；不用提供任何 API key。對齊期間後再計：

1. AI 每個端點的 `prompt_tokens`、`completion_tokens`、其中 reasoning/cache 明細、實際 cost、model/provider、成功／失敗。
2. 每個規劃回合的 Places／Routing／圖磚耗用與重試次數。
3. 成本分母分開列「發起規劃」「成功回傳方案」「完成需求」，不把三者混稱一次服務。
4. 輸出平均值、P50、P95、失败成本，以及每月訂閱攤提。充值金額是現金流，不等於當期耗用費。

這些資料到齊後，才適合在簡報改寫成「我們量測到平均每回 X 元」。[OpenRouter 官方用量與 Activity 說明](https://openrouter.ai/support/)
